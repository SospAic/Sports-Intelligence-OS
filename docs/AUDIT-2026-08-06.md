## 结论

源码已经具备可用的垂直切片：账号与作品监控、新闻与热点、规则、自动化、生成、下载、媒体资源和设置均有真实 API / 数据库 / 异步任务链路；本轮后端回归为 **171 passed，1 warning**，根目录契约测试为 **35 passed**。但当前 `localhost:8080` 仍是旧前端实例，尚未加载本轮源码，因此不能把“源码通过”当作“已部署完成”。

上线前必须完成：

1. 使用当前源码重建并重启 web/api/worker/beat，执行 `alembic upgrade head`，再做一次浏览器验收。
2. 轮换本机 `.env` 中已经使用过的外部 API、LLM、通知凭证；凭证值未进入 Git，但已在本机配置中存在，不能继续沿用。
3. 清理或隔离运行库中的测试/失效账号（例如重复账号、`404 Not Found`、`Delete Test Account`），不要直接删除可追溯的历史数据。
4. 对 Bilibili 登录墙、TikTok/抖音反爬、新闻源失败设置永久失败分类和熔断，避免无效重试持续占满任务队列。

## 本轮修复

- 所有产品默认名称和本机 `.env` 用户界面名称统一为 `Content Intelligence OS` / `内容智能生产平台`。
- 热点情报“采集真实数据”统一为“开始采集”；情报分析页去掉重复标题并扩展到 Tab 内容区。
- 删除设置页数据库与 Redis Tab；模型 Provider 切换后可拉取模型清单。
- 下载页改为“解析地址 → 预览 → 选择资源 → 提交异步任务 → 下载记录”路径；下载弹窗自适应视口居中。
- 增量同步采用重叠窗口并合并媒体清单，避免重复全量扫描和封面/字幕被覆盖。
- 媒体详情补齐封面优先级、视频播放器占位、字幕文件卡片和双语字幕播放器。
- 禁用已确认失效或相关性不足的默认新闻源，迁移隔离历史失效源并保留来源审计信息。
- 补齐下载提交和评论采集两个异步写入接口的 CSRF 校验与工作区角色校验。

## 运行实例中仍可复现的问题

当前 `localhost:8080` 是未重建旧实例，实测仍出现旧品牌、旧下载表单、旧热点按钮和数据库/Redis Tab；这不是源码未修改，而是部署版本滞后。旧数据还显示同步失败较多、Bilibili 登录墙错误、重复/测试账号和旧 TikTok 下载失败记录。重建后仍应保留这些失败记录用于审计，但应提供“不可重试 / 需要凭证 / 重新尝试”的明确操作。

## 下一阶段建议

### P0：上线门禁

- 镜像构建、迁移、健康检查和浏览器冒烟测试纳入单一发布脚本。
- 账号/来源/任务增加 `login_required`、`permanent_failure`、`retryable` 分类；永久失败自动暂停而不是继续重试。
- 所有外部凭证只保存密文或引用，日志和错误卡片只显示脱敏状态。

### P1：运营可靠性

- 增加来源健康分、最近成功时间、延迟、失败率、连续失败次数和自动熔断恢复时间。
- 同步任务使用游标、断点续传、分页进度和可恢复重试；大账号按优先级和配额调度。
- 增加数据新鲜度、采集覆盖率、失败率和队列等待时间的 SLO 看板。
- 将账号清洗、去重、凭证检查和“首次同步预览”做成引导流程。

### P2：生产平台能力

- 引入草稿 → 编辑 → 审核 → 发布/导出 → 复盘的内容生命周期、版本、评论和审计。
- 作品、账号、选题、规则、Prompt 和生成物建立统一的内容资产关系及引用证据。
- 增加内容日历、素材库、批量导出、平台规格校验和团队审批。
