## 一、核心目标达成：账号同步速度/效率对齐独立下载器

原同步对登录墙 / 反爬账号反复重试，既浪费 worker 又无法给出可操作结论。本轮重构已彻底解决。

### 实测对比（同一账号，重构前后）

| 账号 | 重构前 | 重构后 | 状态 |
| --- | --- | --- | --- |
| TikTok `@nba` | 2m53s（retry_exhausted） | **44.4s**（login_required） | 提速 3.9× |
| TikTok `@olympicsbringsustogether` | 重试耗尽 | **50.4s**（login_required） | 快速失败 |
| 抖音 `@…c2e98` | 126.6s（degraded / 占位名「的抖音」） | **42.5s**（login_required） | 快 3× |
| Bilibili（某账号） | 重试耗尽 | **6.3s**（login_required） | 快速失败 |
| YouTube `@BWF`（正常路径） | 16.4s | **12.3s**（success） | 无误伤 |

错误码从不可操作的 `retry_exhausted` 变为可操作的 `login_required`，前端可据此提示「配置该平台的登录态 / 凭证」。

### 落地的关键机制

1. **快速通道**（#91–#94）：扁平账号枚举 + 并发详情抓取 + 跳过已知作品，避免重复全量抽取。
2. **登录墙快速失败**（#65/#66/#68/#69/#75）：yt-dlp 永久错误（登录墙 / 地域 / 已删除）映射为**不可重试**异常；保留浏览器回退通道，浏览器也失败才终态。
3. **反爬空壳页守卫**（#69）：四平台统一识别「HTTP 200 但未水合」页面（占位名如「的抖音」/「UID 123」/@handle），抛 `LoginRequiredError` 而非写回错误账号名。
4. **rehydration 反爬错误**（#65）：TikTok "universal data for rehydration" 先走升级恢复通道（mobile-API `app_info` 轮换），**用尽后**才判非重试，避免 Celery 重试阶梯放大墙钟。
5. **字幕下载 empty 语义**（#66）：`explain_empty_download` 给出明确诊断——「平台无字幕轨（非设置问题）」/「语言不匹配」/「清晰度不存在」/「未开启任何产生文件的选项」。
6. **并发 / 超时压测**（#76）：12 账号并发同步无死锁、锁全释放、墙钟预算内终态；病态慢适配器可被 `wait_for` 超时取消，不会无限挂起。

## 二、质量守护体系（已建立）

- **静态门禁**：`ruff check` + `ruff format --check` + `mypy app`（CI 拦截）。
- **测试覆盖**：登录墙 46 + 导航 4 + 并发压测 2；全量套件 **526 passed / 6 deselected / 0 failed**（16 分钟）。
- **部署流程**：源码烘焙进镜像 → `docker commit` api/worker/beat 三镜像（beat 带 `HEALTHCHECK NONE`）→ `docker compose up -d --no-build --force-recreate`。

## 四、风险与注意事项

- **Git 仓库历史**曾在 08-06→08-09 因外部程序持续删除 `.git/objects` 而损坏，已压扁重建为 `7a690bc` 并**禁用 auto-gc**（`gc.auto=0`）。本地切勿再跑 `git gc`，避免复发。
- 全量测试套件存在若干与本次改动无关的**历史 flaky / 集成失败**（账号死锁、browser CDP、generation LLM-gateway、auth CSRF、editorial/automation）。本轮新增测试均独立通过，无回归。
- 镜像构建走 `docker cp` + `commit` 旁路（pypi 长期不可达），adapter / 服务层修复需 **api + worker 双容器**同步。
