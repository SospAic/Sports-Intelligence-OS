# 严格阶段顺序与验收计划

更新日期：2026-07-25

## 全阶段质量门

每个 Prompt 结束前统一执行：检查现有代码与未提交变更；确认向后兼容；运行并修复测试；更新相关文档；更新 `docs/STATUS.md`；报告完成、未完成与数据真实性边界。

阶段之间采用硬门禁：只有当前阶段验收完成且用户提交下一 Prompt 后才前进。

## Prompt 00：项目总控与长期上下文

交付项目宪章、完整产品上下文、严格阶段顺序、真实性红线、首期范围和可自动验证的上下文契约。不初始化业务应用。

验收：长期上下文文件完整；Prompt 00–11 顺序可机检；首期垂直切片、默认技术栈和 Mock 边界均有文档；契约测试通过。

## Prompt 01：项目规划与架构设计

交付系统上下文图、容器/模块边界、关键数据流、目录规划、API 约定、异步任务策略、部署拓扑、威胁与风险清单、架构决策记录和分阶段任务拆解。

验收：适配器/Provider/领域边界清晰；同步、生成、通知链路可追踪；不提前引入重型组件；计划覆盖首期垂直切片。

## Prompt 02：初始化项目与基础设施

初始化前端、后端、数据库迁移、任务进程、共享配置、认证骨架、Docker Compose、开发/生产环境模板、质量工具和 CI 基线。

验收：一条命令启动依赖与服务；健康检查可用；秘密不入库；最小前后端与任务测试通过。

## Prompt 03：统一账号和作品数据模型

实现用户/工作区、平台账号、作品、账号快照、作品快照、指标定义与派生指标等统一模型、迁移、仓储/服务和 API。

验收：多平台字段可扩展；历史快照不可被当前值覆盖；平台缺失字段、推算字段和来源信息表达准确；筛选、排序、比较基础契约有测试。

## Prompt 04：平台适配器与监控任务

实现平台适配器协议、YouTube 官方 API、通用 Mock Adapter、账号接入、作品/快照同步、手动任务、Celery Beat 定时任务、重试限流和错误日志。

验收：无密钥时不会伪装真实调用成功；Mock 显著标识；YouTube 响应映射有契约测试；同步幂等。

## Prompt 05：体育新闻聚合系统

实现新闻源 Provider、RSS、文章标准化、列表/详情、基础去重、事件关联基础、来源与时间字段以及采集任务。

验收：发布时间与抓取时间分离；原始链接和来源可追踪；去重结果可解释；错误源不阻塞其他源。

## Prompt 06：7.9 规则中心与可视化编辑器

导入并保存 7.9 原文，解析为章节/子章节/规则等结构，支持展示、编辑、版本、草稿/发布、对比、回滚、导入导出和基础规则测试。

验收：原文完整性可校验；结构化规则能追溯原文位置；依赖/冲突/强制性可表达；不能仅保存一个大文本字段。若源文件缺失，本阶段不得宣称导入完成。

## Prompt 07：Prompt 工作流与内容生成系统

实现 Prompt 模板版本、LLM Provider 接口、模型配置和 Research 到 Final Output 的持久化工作流，记录输入、版本、参数、各阶段产物、Token、耗时、成本、评分与采用状态。

验收：不是单文本框直调；可使用明确的测试 Provider；联网事实核实状态清晰；失败可恢复且过程可审计。

## Prompt 08：实时规则引擎与推送系统

实现结构化条件树、窗口/连续/冷却/去重语义、事件触发、统一通知接口，以及首期通知渠道。至少打通一个自定义监控规则和邮件或 Webhook 端到端路径。

验收：定义与执行分离；重复事件不会通知风暴；通知凭证安全；各渠道错误隔离；未配置渠道不显示成功。

## Prompt 09：前端管理后台

完成登录、账号/作品、新闻、规则/Prompt、生成工作流、自动化、通知、事件日志和设置界面的完整交互，并接入真实 API。

验收：不是静态原型；关键列表支持筛选/排序/分页；空/错/加载状态完整；Mock 数据显著标记；关键流程具备端到端测试。

## Prompt 10：测试、文档与验收

补齐单元、集成、契约与关键 E2E 测试，执行迁移/恢复/安全与启动验收，完成中文 README、配置、API、适配器、运维和故障排查文档。

验收：Docker Compose 从干净环境启动；首期垂直切片逐项留证；测试稳定；已知限制与真实集成验证状态公开。

## Prompt 11：最终代码审查与修复

对安全、正确性、数据真实性、并发、幂等、性能、可访问性、可维护性和文档一致性进行最终审查，按优先级修复并回归测试。

验收：阻断级和高优先级问题清零；回归测试通过；最终完成矩阵准确；没有把计划能力写成已实现能力。
