## 本轮直接开发

原信息中心的已读标记写入浏览器 `localStorage`，导致换设备、换浏览器或同一工作区的其他成员无法共享处理状态，也无法在服务端验证读回执。本轮新增：

- `inbox_read_states` 表，按 `workspace_id + user_id + item_kind + item_id` 唯一隔离，记录持久化 `read_at`。
- `GET /api/v1/inbox/read-states`：批量读取当前用户对任务/通知记录的读状态。
- `POST /api/v1/inbox/read-states` 与 `/bulk`：单条或批量标记已读，要求 CSRF，重复调用幂等。
- 首页铃铛与 `/notifications` 历史页改用后端读回执；网络失败时只保留临时乐观状态并回滚，不把失败显示成已持久化成功。
- 补充工作区/用户隔离、幂等、批量去重和非法 key 的 API 测试。

这一步只表示“已读/已处理信息记录”，不改变同步任务、通知投递或审核条目的业务状态，也不伪造第三方渠道已完成。

## 行业案例映射

- Sprout Social Smart Inbox 的核心是统一流、筛选、标签、完成状态、团队协作和自定义视图；本项目应把同步、通知、审核和告警逐步汇入一个可操作队列，而不是继续增加孤立的结果页。参考：[Smart Inbox](https://sproutsocial.com/features/smart-inbox/) 与 [功能列表](https://sproutsocial.com/features/)。
- Buffer 将草稿审批、评论 Notes、权限和共享日历放在同一协作流程；本项目已有审核队列和评论线程，下一步应增加邀请/角色、内容日历和“批准≠已发布”的发布状态机。参考：[Collaborate](https://buffer.com/collaborate) 与 [审批草稿](https://support.buffer.com/article/665-managing-and-approving-draft-posts)。
- Hootsuite 的趋势产品强调实时信号、主题聚类、趋势阶段、告警和竞品基准；本项目应让每个热点显示窗口、样本、证据、阶段和下一动作，而不是只突出单一总分。参考：[Trend Research](https://www.hootsuite.com/platform/trend-research)。
- Tubular 强调跨平台统一视图、内容分类和新兴趋势/创作者比较；本项目已有账号横向对比，后续应加入同发布时间窗口、平台覆盖和数据可比性提示。参考：[Tubular](https://tubularlabs.com/)。

## 后续开发方向

### P0：先做真实闭环与可信度

1. **发布与表现归因**：增加 `Publication`、固定窗口 `PerformanceAttribution`，关联生成运行、审核版本、规则/Prompt、实际作品和来源；展示 1/3/6/24/72 小时与 7/30 天表现。没有官方/授权分析时明确显示“需要条件”。
2. **热点生命周期与事件级榜单**：引入 `emerging / accelerating / peaking / declining`，按规范事件聚合跨平台话题/视频，保留算法版本、窗口、样本量、去重键、贡献因素和证据，避免同一事件重复占榜。
3. **真实 canary 与 SLO**：为平台 Adapter、新闻源、LLM、通知 Provider 建立每日合成检查，记录字段完整率、限流、失败分类、恢复时间和来源类型；不能用测试 Fixture 代替真实凭证验证。
4. **索引漂移与恢复**：先处理 `alembic check` 已报告的保存视图/媒体生命周期索引漂移，再执行备份恢复、Redis AOF、Worker 中断和通知超时演练。

### P1：把运营队列变成内容操作系统

1. **统一收件箱**：加入未读/待处理筛选、标签、保存视图、批量完成、负责人和 SLA；把审核评论、订阅告警和失败任务作为可追踪的队列项。
2. **证据包**：规范人物/球队/赛事实体，把 Article、发布时间、原始 URL、摘录位置、视频、字幕和生成字段连成证据图；生成只能引用冻结证据包。
3. **内容排期与发布 Adapter**：先做排期/待发布状态和权限，再按官方 OAuth/授权接口逐平台验收；禁止在未有 Adapter 时显示“已发布”。
4. **检索可解释性**：支持保存查询、索引新鲜度、召回来源和片段定位；检索结果应能直接创建选题或审核条目。

### P2：规模化智能能力

1. 标题/Hook/叙事顺序/缩略图的观察性实验，区分真实 A/B 与非因果对照。
2. 受授权 Analytics 数据支持的受众、地域、语言、完播和变现分析。
3. 版权/许可/地域限制/到期时间的素材权利中心。
4. 只有容量与延迟证据证明必要时，才引入更重的队列或检索基础设施；当前继续保持 PostgreSQL + Redis + Celery。

## 数据真实性与验收边界

- 公开页可获取指标继续标记 `live` 并完整呈现；私有 Analytics、完播、平均观看时长、流量来源和 RPM 缺少条件时只显示具体所需条件。
- `mock`/Stub 仅用于契约测试，不在生产 UI 中作为真实平台成功；`imported` 必须保留来源文件或 URL。
- 本轮新增读回执是产品操作数据，不是平台数据；它不改变外部同步或通知结果。
- 任何发布、通知发送、真实平台同步和备份恢复仍须在对应权限/凭证和可恢复环境下单独验收。
