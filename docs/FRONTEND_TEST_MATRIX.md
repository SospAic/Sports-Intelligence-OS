# 前端功能点与测试覆盖矩阵

## 为什么之前会遗漏

组件测试只能证明被渲染的组件，主流程测试只能证明主动选择的路径。若没有页面路由清单、交互动作清单、API 契约和权限/空错态矩阵，二级按钮（例如“检查运行时”）很容易没有被执行。

## 当前门禁

`apps/web/lib/frontend-function-manifest.ts` 是前端页面功能清单，自动登记每个 Next.js `page.tsx` 路由的测试层级和关键动作。`frontend-function-manifest.test.ts` 会扫描页面文件并比较路由集合：新增页面未登记时测试失败，删除/改名造成的陈旧登记也会失败。

每个页面按三层执行：

- `smoke`：路由可加载、权限边界、主标题和首屏空/错/加载态；
- `interaction`：筛选、分页、弹窗、按钮请求、详情跳转和失败提示；
- `workflow`：从输入到 API、任务状态、结果、审计或回滚的完整链路。

每个关键动作还要至少覆盖：成功、加载中、空数据、后端错误、无权限、重复点击/幂等和敏感字段脱敏（不适用时写明原因）。真实第三方凭证缺失时，用明确标识的 Mock/契约响应测试失败和降级，不把 Mock 成功写成 live 成功。

## 本轮新增覆盖

- 视频解析运行时：`检查运行时` 会显示检查中状态，调用 `/downloads/runtime`，成功/降级/失败都会有 toast 和最近检查时间。
- 设置概览：同时检查核心服务、平台就绪度、LLM、视频解析运行时、部署参数、语义索引、通知、媒体存储和新闻源；“重新检查全部”会重新请求全部诊断接口。
- 自动化断言：`editor-flows.test.tsx` 增加运行时检查和设置概览测试；路由清单门禁防止新增页面漏登记。

## 2026-08-18 全链路验收记录

- 盘点范围：`FRONTEND_FUNCTION_MANIFEST` 登记 46 个 Next 页面路由；静态扫描覆盖约 80 个客户端组件文件及其按钮、表单变更、查询/变更请求和关键跳转；每个路由登记 smoke / interaction / workflow 层级与关键动作。
- 路由冒烟：`apps/web/e2e/route-smoke.spec.ts` 在 mobile / tablet / desktop 三个视口登录后遍历全部静态路由，并继续跟随页面中可发现的动态详情链接；检查重定向、工作区加载卡死、Application Error、未处理运行时错误和页面错误。
- 组件与契约：Web Vitest `26 files / 84 tests passed`；包含登录、规则编辑、Prompt、内容生成、下载设置、字幕、主题、运行时检查、设置概览、Inbox、账号对比和分析筛选等纯逻辑/组件链路。
- 浏览器全量：Playwright 共 117 项，`111 passed / 6 skipped / 0 failed`，覆盖登录与权限边界、三视口无障碍、键盘导航、移动抽屉、用户菜单、未读信息弹窗、截图和全路由冒烟。6 项跳过是按 `isMobile` 条件跳过的桌面/平板移动抽屉用例，不是未执行失败。
- 后端联动：趋势可靠性回归 `8 passed`；真实 30 日热点聚合接口在当前数据规模下返回 200，实测约 10.5 秒。数据规模与外部平台限制仍按 `source_kind` 和“需要配置/授权”边界展示，不把 Mock 当作 live。

### 覆盖边界

路由冒烟能保证页面入口、权限、加载态和动态详情入口不遗漏；它不会在没有安全测试数据的情况下自动点击每个具有破坏性的删除、发布、重放或外部平台写操作。此类动作由组件/契约测试和各页面登记的 workflow 清单覆盖，真实平台发布、私有 Analytics、登录墙和验证码仍需相应用户授权后单独验收。

## 真实浏览器验收要求

部署后至少执行一次登录态浏览器巡检：按清单逐页打开，逐个执行 `workflow` 关键动作，再抽样执行 `interaction`；记录页面 URL、请求、响应状态、toast/空错态、控制台错误和截图。登录墙、验证码、平台授权等不能绕过，需由用户完成授权后再继续；没有真实凭证的能力必须显示“需要配置/需要授权”。
