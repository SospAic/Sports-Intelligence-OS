# 热点情报中心重构说明

更新时间：2026-08-18

## 结论

热点情报中心从“多个指标页签”调整为“热点机会工作台”。榜单只负责发现机会，话题详情负责核验事实与内容样本，分析和衍生能力作为按需工具出现。这样一个热点的最小可用单元是：

`话题 → 新闻证据 → 视频样本 → 指标口径 → 可执行下一步`

原实现的主要问题是：`TrendTopic` 只有热度、增长率和样本量；新闻、视频和评分解释分散在不同区域；RSS 新闻被投影为 `TrendVideo(platform=web)`，导致页面看得到数字却难以追溯原文；衍生话题、智能搜索和情报分析作为薄页签存在，用户需要在多个入口之间来回切换。

## 当前实现

### 1. 证据链接口

新增 `GET /api/v1/trends/topics/{topic_id}/evidence`，返回：

- `topic`：当前去重后的 live 话题快照；
- `news`：标题、摘要、原文链接、来源、来源类型、Provider、发布时间、来源可信度和匹配方式；
- `videos`：平台、作品标题、作者、封面、原文链接、实际返回的播放/点赞/评论/分享、高潜分、观测时间和匹配方式；
- `coverage`：时间窗、证据数量、直接采集引用数量和缺失条件。

匹配优先级为“采集器保存的来源引用”→“视频实体引用”→“标题/摘要实体匹配”。旧快照没有来源引用时，仍会使用有界的 72 小时回退检索；RSS 趋势快照会透明地回退为新闻链接，而不会继续把它伪装成视频。

### 2. 采集器补齐来源引用

公开 RSS/Atom 话题聚合现在保留最多 10 条 `source_article_refs`，包含原始 external id、URL、标题、摘要、来源和发布时间，并写入 `evidence_version=trend-topic-evidence-v1`。已有 JSON metadata 不需要迁移，新采集批次即可使用精确引用。

### 3. 前端工作台

- 删除“趋势榜单 / 衍生话题 / 智能搜索 / 情报分析”四个薄页签；
- 热点榜单、新闻事件、关键词趋势、视频样本和平台概览在同一个工作台按任务顺序呈现；
- 每个话题增加“查看证据”入口，右侧抽屉显示新闻链接、摘要、来源时间、相关视频、真实互动字段、覆盖说明和评分解释；
- 趋势分析、生成衍生角度、智能搜索改为工作台顶部的按需工具按钮，保持原能力但不再抢占主导航；
- 空状态明确给出“需要启用新闻源/需要平台公开数据或监控账号”等条件，不以估算数填充。

### 4. 本轮交互层调整

工作台顶部增加三个“索引入口”：热门话题、热门新闻、热门视频。入口展示当前真实榜单数量，点击后只滚动到对应榜单，不改变当前上下文；榜单行再进入下一层详情：

`索引入口 → 榜单行 → 详情抽屉 → 原文/视频证据`

- 热门话题：进入话题证据抽屉，继续查看新闻证据、相关视频、评分解释和覆盖边界；
- 热门新闻：点击事件行打开新闻详情抽屉，继续查看事件指标、摘要、报道列表、来源和发布时间；
- 热门视频：点击视频行打开视频详情抽屉，继续查看封面、作者、互动指标、来源和原视频；
- 趋势分析、生成衍生角度、搜索这个赛道：改为顶部工作台工具切换，工具内容在原页面位置渲染，并提供“返回机会总览”，不再追加到页面最底部。

### 5. 分类数据修复

- 分类列表新增 `GET /api/v1/trends/categories`，只返回当前时间窗、平台筛选下有真实 `live` 样本的分类，并同时给出话题数和视频数；没有样本的分类不再显示为空的可点击标签。
- `/trends/topics` 与 `/trends/videos` 增加服务端 `category` 筛选。前端不再只过滤当前第一页，因此分类数据量不受全局榜单分页影响。
- `sports`、`general_sports`、`general`、`sport` 等历史别名统一为“综合体育”；补充 Olympic、badminton、NHL、MMA、volleyball、swimming、athletics 等真实标题词的归类。该规则只改变真实内容的分类，不生成虚假样本。

### 6. 标签质量与层级规则

- 默认标签优先级为：具体话题标签（显式 `#hashtag`）→ 具体事件（世界杯、奥运、公开赛、季后赛等）→ 人物 → 队伍 → 联赛 → 地点。
- `football`、`basketball`、`sports`、`ESPN`、`highlights`、`FYP` 等体育大类、媒体名和平台噪声不作为默认热点标签；它们仍可参与判断内容是否属于体育，不进入机会榜单。
- 新采集在词表层过滤，历史 `live` 快照在读取层按同一规则过滤，并向关键词接口元数据写入 `label_type`、`label_priority`、`label_source`，保证筛选可解释且不改写原始来源。
- 规则采用精确泛词黑名单 + 实体抽取，不用“播放量高”掩盖标签无意义；后续可在设置中扩展工作区级排除词和实体词典。

### 7. 衍生角度与赛道搜索的可审计历史

热点工作台的两个按需工具现在都以“每次运行”为一条不可覆盖的历史记录：

- 衍生角度新增 `derivative_runs` 运行记录及 `GET /api/v1/trends/derivatives/runs`、`GET /api/v1/trends/derivatives/runs/{run_id}`；每次生成保存原始平台搜索结果、英文过程日志、角度结果、状态、降级原因和完成时间，角度行通过 `derivative_run_id` 回溯到具体运行。
- 赛道搜索继续保存 `SearchQuery` / `SearchAnalysis`，并补充英文查询、过程日志和翻译缓存；`GET /api/v1/trends/search` 是历史索引，`GET /api/v1/trends/search/{query_id}` 返回该次完整结果，`POST /api/v1/trends/search/{query_id}/translate` 返回指定语言投影。
- 两条链路的搜索过程、LLM 提示语义和结果展示以英文为基线；中文等输入会记录 `source_language`，生成英语投影。翻译服务不可用时显示明确的 degraded/条件提示，不把原文或估算文本伪装成译文。
- 搜索结果保留平台实际返回的 `view_count`、`like_count`、`comment_count`、作者、发布时间和链接，并额外展示 `heat_score`。该热度是可解释的对数代理指标（搜索链路还考虑返回的互动字段），`metric_source` 明确标记其为派生值，不冒充平台原生热度。
- 前端支持 English、简体中文、日语、韩语、西班牙语、法语、德语和葡萄牙语；翻译只改变文本投影，不丢失原始 URL、平台字段、来源指标、证据和历史运行。
- 网站导航、按钮、字段名、状态、提示和历史记录等界面文案始终保持中文；默认英文仅适用于后台执行日志、英文搜索词、来源结果标题/作者、分析摘要和衍生内容。切换语言时只翻译这些内容投影，不切换网站界面语言。

## 指标与数据边界

- `live` / `imported` 来源可进入证据链；`mock` 不进入默认热点榜单；
- 播放、点赞、评论、分享、封面、标题只显示适配器实际返回值；
- 完播率、平均观看时长、流量来源、变现 RPM 等私有指标不属于该接口的可推算字段；没有对应平台权限时必须显示条件说明；
- 聚合仍按平台 + 标题/实体的机会簇去重，`TrendTopic.id` 只代表快照，不代表永久话题实体；
- 72 小时是详情证据的默认窗口，与现有热点列表 24/48/72 小时筛选保持一致；更长历史趋势继续走 `/trends/aggregate`。

## 行业实现参考

这次信息架构吸收了四类成熟模式：

1. Google Trends 将趋势发现与趋势详情放在一起，详情可继续查看时间序列、分解、新闻来源，并支持比较和导出；
2. Feedly AI Feeds 将来源筛选、去重、摘要与保存/后续动作连成一个阅读工作流，而不是只给一个声量数字；
3. GDELT 的事件记录保留媒体发现时间、来源和时间线，强调“发生时间”和“被报道时间”不能混为一谈；
4. Brandwatch 的主题分析将峰值、驱动主题和话题聚类结合，用于从监测结果进入内容机会判断。

本项目没有复制这些产品的封闭数据或算法；只借鉴“证据可追溯、聚类可解释、发现后可行动”的产品结构。

## 下一步扩展方向

1. 将新闻 `Article` 与热点快照改为显式 `TopicEvidence` 关系表，支持人工确认、证据排除和事件时间线；
2. 增加“跨平台同题”证据分组，但保留 suggested/confirmed/rejected 状态，不把相似标题自动当作同一事实；
3. 在话题抽屉内接入现有衍生引擎，生成“已有内容缺口 / 适合平台 / 素材需求 / 事实核验清单”；
4. 引入热点生命周期（emerging、peaking、cooling、closed），同时展示峰值驱动证据和降温原因；
5. 对每条证据增加采集批次、抓取延迟、来源健康和字段可用性，以便运营人员判断“热”是真实升温还是单源噪声。
