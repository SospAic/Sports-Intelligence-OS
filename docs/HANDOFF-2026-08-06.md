当前项目已经具备可启动的 Docker Compose 单机垂直切片：账号与作品监控、新闻/热点、规则自动化、内容创作、视频下载、媒体信息、LLM Provider、视频内容搜索和 Docker 内置人工登录浏览器均已接入统一后台。核心路径不是静态演示，后端、任务队列、数据库迁移和前端生产构建均已验证。

## 3. 平台与人工登录入口

Docker 浏览器当前登录页映射如下。后续修改平台入口时，必须同步更新 `apps/api/app/services/platform_session_capture.py`、测试、前端提示和本文。

| 平台 | 当前登录入口 |
| --- | --- |
| YouTube | `https://accounts.google.com/ServiceLogin?service=youtube` |
| TikTok | `https://www.tiktok.com/login/phone-or-email/email` |
| 抖音 | `https://sso.douyin.com/?service=www.douyin.com%2Flogin` |
| Bilibili | `https://passport.bilibili.com/login` |

登录流程是“用户在浏览器中人工完成登录，系统保存会话”，不是账号密码自动化登录。系统不代填密码、不绕过验证码或 MFA、不绕过平台安全限制。Cookie 和 Playwright storage state 仅加密保存，提取时按当前平台域名过滤；日志和接口不应回显敏感内容。

## 7. 已知限制与风险

1. YouTube 429、登录墙、TikTok/抖音/Bilibili 反爬、地区限制和会话过期仍可能导致 yt-dlp 或指标同步失败；错误必须进入可审计的失败/降级状态，不能声称成功。
2. 完播率、平均观看时长、流量来源、变现指标等私有指标需要相应官方 API 或授权会话；无条件时 UI 应显示具体“需要条件”。
3. 视频内容搜索的真实命中依赖可取得的视频文件、分析 Provider、上传限制、成本和版权边界；严格匹配门禁必须继续保留证据和时间段，不能退回标题匹配。
4. LLM 模型下拉展示的是 Provider 目录/预置能力；只有配置真实凭证并发起探测，才能确认模型当前可调用。
5. 历史账号/作品的封面、字幕和媒体资源不会自动凭空补齐，需要重同步、公开资源可达或人工下载归档。
6. Docker 浏览器的登录状态保存在 profile volume；容器重建不应删除该卷，但平台仍可能主动使会话失效。
7. Git 自动维护仍可能提示 `refs/heads/testflat` 坏引用以及用户配置目录权限警告；这不是本轮业务代码错误。处理 Git 元数据前必须先备份并单独确认，禁止用破坏性命令清理。
