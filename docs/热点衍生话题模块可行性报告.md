# 热点衍生话题与智能搜索分析模块 — 可行性报告

- **文档类型**：可行性报告（Feasibility Study）
- **日期**：2026-08-03
- **归属项目**：Sports Intelligence OS（体育情报操作系统）
- **作者**：AI 助手（基于现有代码库盘点 + 市场对标调研）
- **状态**：草案，待评审

---

## 1. 概述与目标

本模块旨在为运营/编辑/内容团队提供一套**跨平台热点洞察与内容选题**能力，分两大核心部分：

- **第一部分（热点衍生话题）**：支持各平台（及汇总）在指定时间段内的热点话题、视频、趋势的详细列表、数据与基础分析；并支持**针对某一热点进行"衍生查询"**——呈现该热点在平台上**已存在的衍生话题**，以及由 AI 分析的**潜在热门衍生话题**。
- **第二部分（自然语言搜索分析）**：支持用**一段自然语言描述**在全网或指定平台检索相关内容，展示命中内容的详情，以及该检索条件本身的**相关热度与配套数据**（含衍生话题、情绪、时间线、平台分布等）。

> **关键结论（先行）**：经代码库盘点，本项目**已具备约 60–70% 的基础能力**（趋势采集、热度评分、跨平台关联、LLM 调用管线、Celery 周期任务、新闻/社媒适配器）。本模块的"净新增"主要集中在两处：**① 衍生话题引擎（AI 生成 + 现有衍生聚类）** 与 **② 自然语言搜索 + 热度分析后端**。因此**可行性高**，可作为在既有 `trends` 模块上的增强而非从零重建。

| 子需求 | 说明 | 现有基础 |

| 详情/数据/分析 | 热度分、增速、爆款视频、解释性洞察 | ✅ `services/trends.py` 已有 dashboard/list/`explain` |
| **衍生查询（核心）** | 对单热点：① 平台已存在的衍生话题 ② AI 预测的潜在热门衍生话题 | ❌ 全新能力，需新建 |

### 2.2 第二部分 — 自然语言搜索分析

| 子需求 | 说明 | 现有基础 |
| --- | --- | --- |
| 文本描述检索 | 一段描述 → 全网 / 指定平台搜索 | ❌ 无搜索端点（grep 全仓仅 `generation` 含 "search"，无检索能力） |
| 命中内容详情 | 标题/URL/摘要/来源/发布时间/指标 | ⚠️ 平台内容可由现有适配器取，但需搜索接入层 |

| 配套数据 | 相关衍生话题、情绪、时间线、平台分布 | ❌ 全新，但 LLM 管线 + 趋势模型可复用 |

## 3. 市场对标（参考系统与平台）

调研了国内外主流热点/趋势/舆情平台，作为功能与数据模型设计的参照。

### 3.1 国内平台
- **百度指数**：关键词搜索热度、地域/时间分布、相关词（related queries）——"检索条件热度"的最佳参照。
- **巨量算数 / 巨量星图**（抖音）：短视频内容趋势、行业关键词、相关词、热点投放预判——"衍生话题 + 平台生态热度"参照。
- **微信指数 / 微信搜一搜**：微信生态讨论与转载。
- **微博热搜 / 知乎热榜 / 快手热榜 / 今日头条热榜 / B站**：即时热点、话题排名、升降——突发热点线索发现。
- **新榜 / 清博指数 / 蝉妈妈 / 飞瓜数据**：跨平台热点、爆款视频拆解、用户画像、话题生命周期（短期爆发 vs 长期趋势）——"衍生话题内容拆解"参照。

### 3.2 国际平台
- **Google Trends**：区域+时间筛选、rising topics、related queries——免费且权威的"检索热度"基准。
- **Exploding Topics**：编辑化趋势页 + 增长信号——"AI 潜在热门话题"参照。
- **BuzzSumo**：病毒追踪 + 互动评分——内容热度评分参照。
- **Brandwatch / Talkwalker / Meltwater / Sprout Social**：Boolean 查询、叙事位移（narrative shift）、情绪、跨渠道仪表盘——企业级社媒聆听，对标"衍生话题发现 + 跨平台"。
- **TikTok Creative Center / Glimpse**：实时社媒情报、多平台趋势。

### 3.3 AI / LLM 趋势分析范式（研究结论）
- **主题建模 + 语义分析**：LLM 将 "plant-based eating / vegan / meatless" 聚为同一趋势，捕捉关键词之外的深层主题。
- **时序建模（temporal modeling）**：识别突增（spike）vs 可持续趋势，季节性与生命周期预测。
- **跨平台动力学**：追踪话题从 Reddit/TikTok → Twitter → 主流媒体的扩散路径，预测轨迹。
- **新兴关联发现**：LLM 能识别 "AI" 与 "fitness coaching" 的上升关联，提前预示新趋势类别——这正是"AI 潜在衍生话题"的理论基础。
- **共识做法**：单一工具不覆盖全貌，需多源交叉验证；早期信号 + 情绪 + 互动质量共同决定 viral 潜力。

### 3.4 对标启示（对本模块的设计输入）

| 对标能力 | 映射到的本模块设计 |
| --- | --- |
| 百度指数 / Google Trends 的 related queries + 热度 | 第二部分"检索条件相关热度"的数据模型 |
| 巨量算数 / 飞瓜的衍生话题 + 爆款拆解 | 第一部分"平台已存在衍生话题"聚类 |

## 4. 现有基础设施盘点（代码库实证）

经只读排查（`apps/api`），可复用资产如下：

### 4.1 已存在的趋势模块（直接复用）
- **模型** `app/models/trends.py`：`TrendTopic`(`heat_score`,`growth_rate`,`rank`)、`TrendVideo`(`breakout_score`)、`TrendKeywordSnapshot`、`CrossPlatformLink`。
- **服务** `app/services/trends.py`：dashboard / list / `explain`（解释性洞察）。
- **采集** `app/services/trend_collector.py`：`TrendCollectorService` —— 由监控内容的 `view_velocity` + YouTube `mostPopular`/`search` 计算热度分（加权百分位 + 置信度收缩）。
- **调度** `app/tasks/trends.py`：`collect_platform_trends` 已由 **Celery beat 每 3600s** 触发，遍历 active 工作区。
- **前端** `apps/web/components/trend-chart.tsx`、`time-range-picker.tsx`、`data-table.tsx` 已可用于趋势可视化与时间筛选。

### 4.2 可复用的横切能力
- **LLM 管线** `app/providers/llm/`：`LLMProvider` 抽象 + `OpenAICompatibleProvider`（**完全异步、支持 SSE 流式**），经 `SIO_LLM_*` 配置；`registry.py` 单例；`services/settings.py` 的 `resolve_llm_provider` 可按工作区解析模型。→ 衍生话题生成与搜索分析直接调用。
- **社媒适配器** `app/adapters/platforms/`：YouTube/TikTok/Douyin 的 **yt-dlp 适配器**（默认）、四平台 Browser 适配器、Bilibili 仅 browser。→ 平台搜索与内容抓取可复用 `list_contents`/`fetch_content`。
- **新闻聚合** `app/models/news.py` + `providers/news/`（RSS/Atom/JSON/Browser）：文章库（title/summary/published_at/source）可作热点与搜索的补充语料。
- **异步基建** Celery worker/beat + Redis + PostgreSQL —— 周期趋势采集与搜索任务的标准范式。
- **配置模式** `services/settings.py` + `AdapterDescriptor`/`config_fields` —— 新模块的"监控平台/刷新间隔/LLM 模型"设置可照搬此模式。

### 4.3 净缺口（需新建）
1. **衍生话题引擎**：AI 生成候选衍生话题 + 平台现有衍生聚类，及其与 `TrendTopic` 的关联存储。
2. **搜索接入层**：全网/平台搜索后端（搜索 API 或适配器搜索），目前完全缺失。
3. **搜索分析后处理**：LLM 对检索结果做热度/情绪/关联/时间线结构化输出。
4. **汇总榜合并**：`CrossPlatformLink` 升级为自动跨平台归一与排名。
5. **前端**：搜索面板、衍生话题图谱/列表（现有 `trend-chart` 可扩展）。

### 5.2 数据模型（扩展方案）
在 `app/models/trends.py` 基础上**新增**：

```python
class DerivativeTopic(Base):
    id, workspace_id, parent_trend_id FK(TrendTopic)
    title                  # 衍生话题标题
    angle                  # 角度: 争议/科普/二创/盘点/幕后/数据可视化...
    source                 # 'ai' | 'existing'
    platform               # 目标/来源平台
    predicted_heat         # AI 预测热度 0-100
    confidence             # 置信度
    rationale              # AI 理由
    existing_content_count # 现有衍生内容数（source='existing' 时）
    existing_heat          # 现有衍生合计热度
    status                 # proposed | validated | rejected
    metadata_json

class SearchQuery(Base):
    id, workspace_id, query_text, scope          # 'web' | platform
    created_by, created_at, status

class SearchAnalysis(Base):
    id, search_query_id
    heat_score              # 检索条件相关热度 0-100
    mention_volume          # 声量估计
    sentiment               # 情绪分布
    timeline_json           # 时间线
    platform_distribution   # 平台分布
    related_topics_json     # 相关衍生话题
    summary                 # LLM 摘要
    llm_model, llm_usage
```

### 5.3 采集层
- **平台趋势**：复用 `TrendCollectorService` + 各平台趋势端点（YouTube `mostPopular`/`search` 已用；补 TikTok/Douyin/微博热榜——后者需 browser 或授权 API）。
- **平台搜索**：新增 `yt-dlp "ytsearchN:<q>"`（YouTube/TikTok 已支持）与 browser 搜索（Douyin/微博，受平台限制）作为"现有衍生话题"的来源。
- **Web 搜索**：接入搜索 API（见 §6）。

### 5.4 衍生话题引擎（第一部分核心）
对某一 `TrendTopic`（或用户粘贴的热点描述/URL）：
1. **现有衍生话题（source='existing'）**
   - 用热点关键词调平台搜索，抓取相关视频/帖子。
   - 按标题/标签做轻量聚类（关键词或 embedding），聚合每簇的 `existing_content_count` 与 `existing_heat`（取 view/like 汇总）。
   - 输出"平台上已经有人在做的衍生角度"列表。
2. **AI 潜在热门衍生话题（source='ai'）**
   - 构造 `LLMRequest`：系统提示定义角度词典与输出 JSON Schema；用户提示含热点标题/描述 + 近期相关趋势摘要 + 目标平台生态。
   - LLM 生成 N 个候选：标题、角度、目标平台、`predicted_heat`(0-100)、`rationale`、建议切入。
   - 落库 `DerivativeTopic(source='ai')`，前端以列表/图谱展示，支持"采纳→生成内容大纲"（可复用 `generation` 模块）。

### 5.5 搜索分析引擎（第二部分核心）
1. **检索**：`SearchQuery.scope` 决定走 Web 搜索 API 或平台搜索；返回标题/URL/摘要/来源/时间/指标。
2. **LLM 后处理**：将检索结果 + 原始描述送入 LLM，结构化输出 `SearchAnalysis`：
   - `heat_score`：综合声量、来源多样性、时效、互动质量的估计热度。
   - `sentiment` / `timeline_json` / `platform_distribution` / `related_topics_json` / `summary`。
3. **详情展示**：命中内容以 `data-table` + 详情抽屉渲染（标题/URL/摘要/来源/发布时间/平台指标）。

### 5.6 API（新增路由，挂在 `/api/v1`）
- `GET /trends/derivatives?trend_id=&scope=` —— 衍生话题列表（existing + ai）。
- `POST /trends/derivatives/generate` —— 触发 AI 衍生生成（异步 Celery）。
- `POST /search` —— 创建搜索（异步）→ `GET /search/{id}` 取 `SearchAnalysis` + 命中列表。
- 扩展既有 `GET /trends` 支持 `time_range` 与 `aggregated` 汇总参数。

### 5.7 前端（新增/扩展）
- 扩展趋势仪表盘加入"衍生话题"Tab（列表 + 简单关系图，可用 `trend-chart.tsx` 改造）。
- 新增"智能搜索"页面：自然语言输入框 + 范围选择（全网/平台）+ 结果面板（热度卡 + 时间线 + 相关话题 + 命中列表）。
- 复用 `time-range-picker.tsx`、`data-table.tsx`、`score-explanation.tsx`。

### 5.8 调度
- 扩展 `tasks/trends.py` beat：新增 `generate_derivative_suggestions`（如每 6–24h 对 top 热点跑 AI 衍生）。
- 搜索为按需（用户触发），走 Celery 异步任务，结果经 WebSocket/轮询返回。

## 7. AI 能力设计要点

- **衍生生成 Prompt**：固定角度词典（争议/科普/二创/盘点/幕后/数据可视化/人物故事）+ 强制 JSON 输出 + 热度评分 rubric（声量基础、平台契合度、情绪触发力、时效窗口）。
- **搜索分析 Prompt**：要求输出结构化字段（热度分、声量、情绪、时间线、平台分布、相关话题、摘要），并基于检索结果的"数量/多样性/时效/互动"反推热度，避免模型凭空编造数字（可要求给出估算依据）。
- **防幻觉**：AI `predicted_heat` 与 `existing_heat` 分离展示；搜索热度须标注"基于检索样本估算"，并链接原始命中以供核验。
- **复用**：调用既有 `LLMProvider`（异步+流式），`resolve_llm_provider` 取工作区模型；可用 `SIO_LLM_FALLBACK_BASE_URL` 兜底。

## 8. 关键挑战与风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 平台访问受限（Douyin/微博需登录/反爬） | 现有衍生抓取不全 | 以 YouTube/TikTok/新闻为主，受限平台标注"覆盖有限" |
| Web 搜索 API 成本 | 第二部分持续费用 | 缓存搜索结果（同查询短窗口复用）、限额、优先用 LLM 联网兜底 |
| 实时性/延迟 | 热点时效敏感 | 周期预聚合热点榜；搜索走异步任务 + 进度 |
| 噪声 vs 信号 | 衍生/热度失真 | LLM 后处理 + 多源交叉验证 + 置信度收缩（复用既有评分范式） |
| 跨平台实体归一 | 汇总榜难做 | 先按平台独立榜，汇总采用"建议链接"逐步升级为自动合并 |
| AI 热度编造 | 误导决策 | 区分 AI 预测 vs 实测，强制附原始证据 |

## 9. 实施路线图

**阶段 0 — 加固与对齐（1–2 周）**
- 给 `GET /trends` 加 `time_range` 与 `aggregated` 汇总参数；前端接 `time-range-picker` 验证既有趋势榜。
- 梳理 `TrendCollectorService` 输出，确认热度分可解释。

**阶段 1 — MVP：衍生话题引擎（2–3 周）**
- 新增 `DerivativeTopic` 模型 + 迁移；`derivatives` 路由。
- "现有衍生"：yt-dlp 搜索 + 聚类（YouTube/TikTok 优先）。
- "AI 衍生"：LLM 生成 + 落库 + 前端列表。
- 复用 `generation` 做"采纳→大纲"。

**阶段 2 — MVP：智能搜索（2–3 周）**
- 接入 1 个 Web 搜索 API（Tavily/SerpAPI）；`SearchQuery`/`SearchAnalysis` 模型 + `/search` 路由 + Celery 异步。
- LLM 后处理输出热度/情绪/时间线/相关话题；前端搜索面板。

**阶段 3 — 增强（持续）**
- 受限平台（Douyin/微博）覆盖、跨平台自动汇总归一、`CrossPlatformLink` 升级。
- 衍生话题反馈闭环（采纳率→优化 AI 评分）、定时 AI 衍生任务。

> **工作量估算**：净新增约 2 个数据模型 + 2 组路由 + 2 个 Celery 任务 + 1 个搜索接入层 + 前端 2 个页面/组件；因 60–70% 基建可复用，**总工期约 6–10 周（1 名全栈 + 1 名算法/LLM 调优）**。

## 10. 可行性结论

**结论：高可行性（推荐立项）。**

- **技术上**：核心依赖（LLM 异步流式管线、Celery 周期任务、趋势采集与热度评分、社媒/新闻适配器、前端趋势组件）均已落地，无需重复造轮子。
- **需求上**：第一部分的基础榜/数据/分析已具备，缺口集中在"衍生话题"；第二部分为全新但技术成熟（搜索 API + LLM 后处理）。
- **风险上**：主要风险为平台访问限制与搜索 API 成本，均有明确缓解路径，不构成 blockers。
- **价值上**：与体育情报场景高度契合（赛事→热点→衍生选题→内容生产闭环），且可复用 `generation` 模块形成"洞察→选题→成稿"全链路。

**建议下一步**：评审本报告的阶段 1/2 范围后，先以"YouTube/TikTok + 新闻"为最小数据源做衍生话题 MVP  spike，验证 LLM 衍生质量与聚类效果，再决定是否引入 Web 搜索 API 与受限平台。
