## 5. 已知问题 / 已修复的关键坑

### 5.1 g4f `PermissionError`（已修复，需记牢以防复发）
- 现象：`g4f-api` 退出（exit 1），日志 `PermissionError: ... './har_and_cookies/private_key.pem'`。
- 根因：命名卷 `llm_experimental_data` 挂载到 `/app/har_and_cookies`，由 **root** 拥有(755)，但 g4f 以 **seluser (uid 1200)** 运行，写不了私钥。
- 修复（一次性，卷权限持久）：
  ```
  docker compose run --rm --user root --entrypoint sh llm-experimental \
    -c "chown -R 1200:1201 /app/har_and_cookies"
  docker restart sports-intelligence-os-llm-experimental-1
  ```
- 若 `docker compose down -v` 删了卷需重做。验证：`docker logs` 见 `g4f-api entered RUNNING` + `curl localhost:8020/v1/models` 返回 200。

### 5.3 字幕历史归档缺口（设计/数据问题，非 bug）
- DB：8974 条 content，1952 有 media，但 `media->subtitles` 非空为 **0** → 字幕 UI 一律显示“无已下载字幕”。
- 根因：TikTok/Douyin 主适配器是 browser（不下载字幕/视频）；仅 yt_dlp（YouTube）产字幕，且需 `sync_settings.download.write_subtitles`。`get_sync_settings_config` 不回填 Pydantic 默认值，存量配置若缺该字段则不同步字幕。
- 真修复：后端 `_config_for`/`get_sync_settings_config` 合并 `YtDlpDownloadSettings` 默认值（write_subtitles=True）+ 对 YouTube 账号重新同步回填。因 pypi 约束本环境未做，列为后续。前端字幕 UI 已就绪，数据到位即生效。

### 5.4 同步慢（预期，非 bug）

## 8. 环境约束（接手前必读）

1. **pypi 持续 `SSLEOFError`** → `docker compose build api/worker/beat` 在 build isolation 拉 setuptools 阶段失败。
   - ✅ 离线改码部署闭环：**`docker cp` 源码进运行容器 → `docker commit <容器> sports-intelligence-os-{api,worker,beat}:latest` → `docker compose up -d --no-build {api,worker,beat}`**。
   - ⚠️ `docker commit` 把 api 镜像当 beat 镜像会继承 api 的 HTTP healthcheck（查 :8000），beat 不监听 8000 → 假 `unhealthy`。提交 beat 用
     `docker commit --change "HEALTHCHECK NONE" <beat容器> sports-intelligence-os-beat:latest`。
   - worker/beat 与 api 共用 `deploy/api.Dockerfile`，worker 跑同步会 import `yt_dlp`；adapter 类修复 **api 和 worker 容器都要 docker cp**。
   - web 镜像：`docker compose build web`（pnpm `--prefer-offline`，不受 pypi 影响）。
2. **api 容器启动即自动跑迁移**（`cd apps/api && alembic upgrade head && uvicorn ...`）→ `up -d api` 自动应用 pending 迁移。
3. **依赖注入从 `app.api.dependencies` 导入**（`CurrentWorkspace`/`DatabaseSession`），不是 `app.api.deps`（不存在，会导致容器启动失败）。
4. **`docker compose up -d` 级联丢弃**：若依赖（如 api）healthcheck 失败，compose 会丢依赖它的容器（web 等）且不自动拉回；修好后需 `docker compose up -d <被丢的服务>`。
5. 宿主 git-bash **没有 `sleep`/`seq`**；跨容器管道可用容器内 `sleep`。删文件用 Python `os.remove`（绕开宿主 safe-delete 钩子）。
