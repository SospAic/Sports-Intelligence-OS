# Sports Intelligence OS 产品需求文档

文档状态：Prompt 01 架构基线  
更新日期：2026-07-25  
适用范围：首期垂直切片与后续扩展边界

## 1. 产品定义

Sports Intelligence OS 是体育内容情报与自动化工作台。它把“发现体育事件—核实事实—组织叙事—生成内容—监控发布结果—触发后续动作”放进一套可登录、可配置、可追踪的系统中。

本产品不是通用爬虫、自动搬运工具或单文本框 AI 包装器。外部数据必须合法获取并保留来源；自动生成必须绑定具体规则、Prompt 和模型版本；任何 Mock 数据必须显著标记。

## 2. 用户与核心任务

| 角色 | 核心任务 | 关键痛点 |
| --- | --- | --- |
| 体育短视频创作者 | 找到值得做的事件，生成可用脚本、标题与素材搜索词 | 信息分散、事实核验慢、叙事质量不稳定 |
| 内容运营者 | 管理选题、规则、Prompt 和生成流程 | 工作流靠人工复制，过程不可追踪 |
| 多账号管理者 | 比较账号/作品增长并及时响应异常 | 平台口径不同、历史数据缺失、提醒滞后 |
| 工作区管理员 | 管理成员、集成、凭证和通知渠道 | 权限与秘密容易混乱，失败缺乏审计 |

## 3. 产品目标与非目标

### 3.1 首期目标

- 提供一个 Docker Compose 可启动、用户可登录和操作的完整垂直切片。
- 用统一模型保存平台账号、作品及不可变历史快照。
- 以 YouTube 官方 API 验证平台 Adapter 设计；以显著标记的 Mock Adapter 支持无凭证开发和测试。
- 从 RSS 形成可追溯的新闻入库、去重、浏览路径。
- 完整保存 7.9 原文并形成可编辑、可版本化的结构化规则。
- 通过持久化多阶段工作流生成内容，而不是直接调用一次模型。
- 用一个自定义监控规则打通评估到邮件或 Webhook 的通知路径。
- 对同步、生成、规则评估和通知保留系统事件与审计记录。

### 3.2 首期非目标

- 不一次性实现所有社交平台、新闻 API、LLM 或通知渠道。
- 不承诺绕过登录、验证码、地区限制或平台反自动化策略。
- 不提供自动发布视频或代替用户登录第三方账号的能力。
- 不引入 Kubernetes、Kafka、ClickHouse、Elasticsearch 或独立工作流引擎。
- 不以大规模实时流处理为首期目标；首期“实时”指数据入库后秒级到分钟级触发。
- 不把推算指标或新闻评分描述成平台官方指标。

## 5. 关键用户旅程

### 5.1 账号监控闭环

管理员配置 YouTube 凭证 → 添加频道 → 手动同步 → Worker 调用 Adapter → 标准化账号/作品与快照 → UI 展示真实来源 → 新快照发布事件 → 自动化规则评估 → 符合条件时投递通知。

### 5.2 新闻到内容闭环

管理员配置 RSS → 定时拉取 → 标准化、去重并关联事件 → 创作者选择热门作品/新闻/事件和规则预设 → 系统自动固定内置 Prompt、工作流与工作区 LLM 配置 → 多阶段生成与事实 QA → 用户直接审阅结构化成品并采用结果。

### 5.3 规则变更闭环

编辑复制已发布规则版本为草稿 → 修改结构化规则 → 执行验证和测试 → 查看版本差异 → 发布 → 新生成运行引用新版本；历史运行仍引用旧版本。

## 6. 非功能需求

| 类别 | 首期目标 |
| --- | --- |
| 可用性 | 单机部署目标 99.5%；单个外部 Provider 故障不拖垮 API |
| 性能 | 普通列表 API 的服务端 P95 小于 500 ms（不含第三方调用）；长任务异步化 |
| 数据一致性 | 数据库事务内写业务数据与 Outbox；Worker 至少一次投递，消费者幂等 |
| 扩展性 | 新 Provider 不修改领域服务主流程；通过注册表与能力声明接入 |
| 安全 | 工作区隔离、最小权限、秘密加密、审计、日志脱敏、依赖扫描 |
| 可观察性 | 结构化日志、trace/correlation ID、任务与外部调用指标 |
| 国际化 | UI 首期中文；时间以 UTC 存储并按用户时区展示；内容语言显式记录 |
| 可访问性 | 关键流程键盘可用，表单有标签，颜色不作为唯一状态表达 |
| 数据真实性 | 每条外部记录有来源类别；Mock 全链路显著标记；推算指标有算法版本 |

性能目标在取得真实负载数据后复核，不作为无数据情况下的规模承诺。

## 7. 首期与后续边界

### 7.1 首期必须实现

身份登录、单工作区基础权限、YouTube + Mock、账号/作品快照、RSS + 基础去重、7.9 原文与结构化规则、Prompt 模板、一个多阶段生成工作流、一个自定义自动化、系统提醒 + 邮件或 Webhook、系统事件、Docker Compose、中文 README 和基础测试。

### 7.2 后续实现

多工作区高级管理、SSO/MFA、更多平台和新闻 Provider、高级事件聚类、更多模型与通知渠道、复杂自定义指标、协作审批、内容日历、自动发布、分布式部署和专用分析/搜索组件。

后续能力不得出现在首期 UI 中并显示为可用；如展示路线图，必须标记“计划中”。

## 8. 产品级成功判定

- 一个新环境可按文档启动并登录。
- 在有真实 YouTube 凭证时，能保留来源地同步频道、作品及快照；无凭证时只运行显著标记的 Mock 路径。
- 一个 RSS 条目能进入新闻详情并保留原始链接，重复拉取不产生重复主记录。
- 7.9 规则原文可校验，至少一个结构化规则可编辑并形成新版本。
- 一次内容生成可查看所有阶段、固定版本、用量和最终产物。
- 一个快照事件可触发规则，并产生一次可追踪、可去重的通知投递。
- 权限、错误、空状态、来源标签和审计在关键路径中可验证。

详细验收映射见 `docs/ACCEPTANCE_CRITERIA.md`。
