# 视频内容搜索引擎可行性报告

## 1. 结论

项目可行，但产品定义必须是“候选视频发现 + 视频内容理解 + 证据化检索”，不能把平台标题、简介、标签或搜索结果当作视频内容命中。

本项目采用分层方案：

1. 发现层：从已授权或允许的公开来源获取候选视频 URL 和基础元数据。
2. 理解层：读取视频的视觉、音频、字幕/语音转写、OCR 和时间片段。
3. 判定层：仅当分析结果包含与查询相关的内容证据，才标记为 `matched`。
4. 交付层：保存来源、分析器、时间戳、证据和失败原因，支持定时运行、筛选和人工复核。

“全网”不等于无限制抓取。系统可以通过来源注册表扩展到更多站点，但每个站点仍受公开访问、API 权限、机器人规则、速率限制、版权和平台条款约束；不会绕过登录墙、验证码、IP 限制或 DRM。

## 2. 行业方案与可借鉴点

| 方案 | 可借鉴能力 | 本项目采用方式 |
| --- | --- | --- |
| YouTube Data API | 通过 `search.list` 发现候选，再用 `videos.list` 补充时长、字幕状态和统计字段；每次搜索最多 50 条且有配额成本 | 作为 YouTube 官方发现适配器；无 Key 时降级为明确标注的公开搜索适配器 |
| TikTok Research API | 支持受限研究场景的视频查询、语音转文字、标签和时间范围过滤 | 作为授权后的 TikTok 发现/转写增强器，不把未授权状态伪装成可用 |
| Gemini 视频理解 | 同时读取音频和画面，可描述、分段、回答内容问题并返回时间点；公开 YouTube URL 可直接作为输入 | 首个真实内容分析器；其它平台通过合法获得的媒体文件或后续分析适配器接入 |
| Azure AI Video Indexer 类服务 | 将转写、OCR、对象、动作、人物、主题统一为带时间戳的洞察 | 作为可插拔的企业分析器方向，保留统一证据契约 |
| Bilibili Open Platform | 通过官方开放平台接入可用能力 | 作为 Bilibili 适配器的优先接入边界，未配置权限时显示不可用 |

## 3. 可行性判断

### 技术可行

- 视觉：关键帧、场景、动作、人物、物体和画面文字。
- 音频：语音转写、语言、音频事件和口播内容。
- 内容语义：将用户自然语言查询转换为可解释的分析指令。
- 检索：第一阶段使用 PostgreSQL 证据文本和结构化 JSON；第二阶段可接入向量数据库或 pgvector。
- 调度：Celery Beat 定时创建运行记录，运行过程可停止、可重试、可恢复。

### 数据可行

候选发现通常可以通过官方 API、公开页面或合规适配器完成；但是四个平台的权限和公开程度不同。系统必须允许每个平台分别返回 `available`、`restricted`、`not_configured`、`failed`，而不是为了“看起来全”而伪造结果。

### 成本可行

视频理解成本随时长和采样分辨率增长。系统默认限制每次运行候选数，并先做去重、时长和来源过滤；长视频优先使用文件引用或分段分析，避免重复上传。真实分析器通过环境变量配置，未配置时仅能完成候选发现和证据状态记录。

### 风险可控

- 来源和内容权限：仅处理有权访问或允许分析的公开媒体。
- 误判：保存分析原文、时间段、置信度和模型版本，UI 允许人工复核。
- 快速运动漏检：固定帧率可能漏掉瞬时动作，后续可对候选片段二次高帧率分析。
- 隐私与安全：不保存平台 Cookie；外部 URL 经过 SSRF/公网校验；API Key 只来自 Secret 配置。

## 4. 当前交付边界

本轮创建的垂直切片包含：

- 视频内容搜索计划、运行记录和候选结果数据模型。
- 四个平台的来源选择和平台能力状态。
- 候选发现与去重。
- Gemini 公开 YouTube URL 视频理解适配器。
- 严格的 `matched / rejected / unavailable / failed` 内容判定。
- 时间戳证据、分析器、来源类型和失败原因。
- Celery Beat 定时运行、手动运行、停止请求和运行历史。
- 前端计划管理、运行状态、内容命中结果、证据展示和能力提示。
- API、服务和分析器契约测试。

当前不宣称已经完成：

- 未提供授权时的 TikTok、抖音私有接口调用。
- 未通过登录墙或验证码获取内容。
- 未将普通网页搜索结果冒充视频内容命中。
- 未引入未经配置的向量数据库或伪造 embedding。

## 5. 后续建议

1. 接入 YouTube 官方 API Key，并将配额、时间范围和去重策略纳入计划配置。
2. 根据账号所在地区和业务资质申请 TikTok Research API 或平台认可的企业能力。
3. 为 Bilibili 和抖音分别实现官方/公开页面适配器，并在平台条款允许范围内补齐媒体获取。
4. 将分析证据拆为片段表，增加关键帧缩略图和人工复核标注。
5. 结果规模上升后接入 pgvector 或专用向量索引，保留 PostgreSQL 作为权威审计库。
6. 增加通知订阅、日报/周报、相似视频聚类和创作素材一键入库。
## 6. 本轮实际落地与上线门槛

- 已落地候选发现、计划调度、运行审计、去重、停止、证据门禁、前端结果展示和 Docker 运行时。
- 已落地 Gemini 视频分析：YouTube 公开 URL 直读；其他三个候选平台通过允许域名校验、yt-dlp 与 ffmpeg 材料化后使用 Gemini Files API。
- 未配置 Key 时系统仍可记录真实候选，但明确不产生内容命中；TikTok/抖音的公开搜索发现仍受平台接口资格、搜索入口和反爬限制，不能宣称“全网无遗漏”。
- 上线前必须完成授权与限额核验、成本预算、数据留存周期、人工复核机制以及每个平台的真实样本验收；随后再增加官方 API、关键帧/片段索引、向量召回、通知订阅和结果质量反馈闭环。
