# 数据指标口径与可信度目录

更新时间：2026-07-30。实现版本：`monitoring-derived-v3`、`trend-opportunity-v2`、`trend-topic-heat-v2`、`objective-weighted-news-heat-v2`。

## 1. 共同原则

- 平台返回的计数、比例和时间按原值保存；未提供为 `null`，真实的零才保存为 `0`。
- 页面区分 `live`、`imported`、`mock`；派生值不能冒充平台原始指标。
- 同名指标的平台定义未必相同。例如 YouTube 的分享数只统计其 Share 按钮触发的分享；跨平台比较前必须查看 Provider 和字段覆盖度。
- 抓取时间只表示观测时间，不替代发布时间。折线图按完整时间戳排序，同日多次观测显示时分，缺失点不补零。
- 推荐分只用于排序和发现线索，不代表事实真伪、版权状态或必然传播结果。

官方字段参考：[YouTube Analytics Metrics](https://developers.google.com/youtube/analytics/metrics)、[TikTok Display API](https://developers.tiktok.com/doc/display-api-overview/)、[TikTok Research API Video Fields](https://developers.tiktok.com/doc/research-api-specs-query-videos/)。

## 2. 账号与作品原始指标

账号快照包括粉丝、关注、总点赞、总播放、作品数和平台可直接提供的互动率。作品快照包括播放、点赞、评论、分享、收藏、涨粉、平均观看时长、完播率、流量来源比例、收入和 RPM。每条快照保存 `source_kind`、`source_provider`、`fetched_at` 和原始响应引用；Provider 没有返回的字段保持不可用。

## 3. 监控派生指标

| 指标 | 计算 | 有效条件与限制 |
| --- | --- | --- |
| 约 1/6/24 小时播放净增 | 最新播放 - 最接近目标窗口的历史播放 | 历史点必须位于目标窗口的 0.75–1.5 倍范围；元数据记录实际小时数和输入快照 ID。它是净增量，不是百分比。 |
| 约 24 小时粉丝净增 | 最新粉丝 - 历史粉丝 | 同一窗口约束；负值表示净流失。 |
| 可观测互动率 | 可用的点赞、评论、分享之和 / 播放 | 缺字段时标为 `partial` 并记录参与/缺失项；全部缺失或播放为零时不可用。 |
| 分享率 / 收藏率 | 分享或收藏 / 播放 | 分子缺失或播放为零时不可用。 |
| 小时播放速度 | 1 小时净增 / 实际小时；无 1 小时时使用 6 小时窗口 | 是观测区间速度，不把作品存量播放除以作品年龄。 |
| 播放加速度 | `(1h 速度 - 6h 速度) / 5h` | 需要两个有效窗口，单位近似为播放/小时²。 |

| 相对账号基线 | 当前播放 / 30 日中位数 | 仅适合同账号内比较；中位数为零或缺失时不可用。 |

## 4. 趋势中心

趋势页只读取最近 24 小时的 `live` 趋势观测；监控作品候选限定为最近 30 日发布的真实作品。

- **话题热度**：样本量百分位 15%、样本总播放百分位 45%、样本平均播放百分位 30%、来源广度 10%。没有播放字段时播放分量不可用，不按零分；至少两个分量才计算。分数按样本数置信度向 50 收缩。
- **话题增长率**：同平台同关键词相邻采集批次的样本总播放变化率。它是受样本集合变化影响的抽样增长，不是平台官方全站趋势。
- **监控作品高潜分**：同平台播放百分位 30%、真实快照窗口播放速度百分位 35%、可观测互动率百分位 20%、72 小时半衰期新鲜度 15%。至少两个分量；按平台样本规模和字段覆盖度向 50 收缩。
- **YouTube 榜单机会分**：官方榜单位置 55%、播放百分位 20%、可观测互动率 15%、72 小时半衰期新鲜度 10%。榜单只有一个样本时位置为中性 50。
- **YouTube 搜索话题热度**：仅从受控体育词和明确 hashtag 聚合，结果频次 60%、搜索排名权重 40%；不再把任意视频标题当成一个话题。
- **同题机会综合热度**：在同一分析窗口内，按 `opportunity-cluster-v1` 将标题高度相似或满足实体重叠与标题相似阈值的真实话题/视频呈现聚为一个运营机会；分数取该机会在各真实呈现中的最大热度/爆发分，不跨平台相加，平台矩阵按每个机会在每个平台/分类单元的最大值累计。它用于避免重复占榜，不等同于已确认的事实事件；跨语言弱匹配和单一泛词不自动合并。
- **热点阶段**：`emerging` 表示最近 6 小时内出现且没有可用增长率，`accelerating` 表示已有话题增长率最高不低于 25%，`declining` 表示最低不高于 -20%，其余标为 `peaking`；视频没有增长率时不伪造增长值。阶段为窗口派生标签，不是平台官方生命周期。

所有分数的 `metadata` 保存公式版本、分量分、实际权重、样本数、置信度、Provider、采集方式、源实体和采集时间。

## 5. 新闻与事件

- **来源可靠度**是工作区对新闻源配置的 0–100 先验评分，不是系统自动事实核验结论。
- **客观事件热度**由来源可靠度、新鲜度、独立来源数和去重后的独立文章数按当前版本化配置加权并重新归一化。新鲜度优先使用事件时间或发布时间，只在均缺失时退回抓取时间并记录降级。
- 相同 `content_hash` 的转载/重复记录仍计入页面“报道数”，但只按一篇独立内容参与文章数量分，防止重复稿刷高热度。
- **推荐分**在客观热度之外叠加当前用户收藏偏好，存于元数据；收藏不会改变客观热度。
- 争议度、视觉度、故事价值只有来源或编辑明确提供时才可用。不可用时 UI 显示 `—`，不显示为 0。
- 单来源事件标记“未交叉验证”；多来源只表示覆盖多个来源，仍不等于事实已经证实。

## 6. 解释与验收

任何用于推荐的条目都应能回答：原始来源是什么、何时采集、哪些字段缺失、公式版本是什么、使用了多少样本、置信度多高。验收数据中 `mock` 只验证契约，不参与真实推荐结果；无凭证或 Provider 不支持时必须显示不可用，不能生成看似真实的成功数据。
