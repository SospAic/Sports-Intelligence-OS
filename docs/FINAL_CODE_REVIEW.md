## 审查要点

### 架构与数据

- Web 只访问本系统 `/api/v1`，没有直接调用 YouTube、RSS、LLM 或通知平台。
- 平台、新闻、LLM 和通知分别使用 Adapter/Provider 注册表；真实集成不会静默切换到 Mock。
- 账号/作品、新闻、规则、Prompt、自动化和运维记录按工作区隔离。
- 作品和快照有唯一约束；账号与作品快照由 ORM 监听器禁止更新，只能追加。
- 发布后的规则和 Prompt 通过创建草稿版本修改；生成运行固定记录规则版本和 Prompt 版本。
- 计数使用 `BigInteger`，比例使用约束后的 `Numeric`；时间字段使用 UTC 语义，服务层兼容 SQLite 无时区返回。

### 安全

- 生产配置拒绝开发 Secret、开发数据库密码和不安全 Cookie。
- Session Cookie 为 HttpOnly/SameSite=Lax，数据库只保存会话与 CSRF Token 的哈希。
- 写接口要求 CSRF；工作区角色和跨工作区访问有测试。
- 通知配置使用 Fernet 加密，API 只返回脱敏摘要；日志不记录请求正文、Cookie 或第三方凭证。
- SQLAlchemy 查询使用参数绑定和枚举式排序字段；React 默认转义外部文本，未使用 `dangerouslySetInnerHTML`。
- 外部输入在默认系统 Prompt 中明确标为不可信数据，不能覆盖系统指令；最终事实来源来自冻结输入而不是模型自称联网。

### 后台任务与 AI

- 同步运行、新闻同步、生成步骤、自动化评估和通知投递均有持久化状态及失败原因。
- 账号同步使用数据库唯一锁；通知投递使用条件更新原子认领及幂等键。
- 外部 HTTP 调用有超时、有限重试、指数退避或限流分类；Celery 也有全局上限和失联租约恢复。
- 自动重写最大次数为 0–5 且每次运行持久化；超限会失败，不会无限循环。
- 原始草稿、最终输出、QA、事实来源、模型、Token、成本、规则版本和 Prompt 版本分别保存。

## 未执行的实机项目

由于当前 Windows 环境没有 Docker、Podman、nerdctl 或 Make，以下项目没有在本机完成真实容器验证：

- `docker compose config` 和 `docker compose up -d`；
- PostgreSQL/Redis 的真实容器连接；
- Celery Worker/Beat 的真实进程心跳和队列消费；
- Caddy 统一入口；
- 使用真实 YouTube、外部 RSS、真实 LLM 或真实通知凭证的调用。

这些项目不能由 SQLite、Mock Transport 或静态 Compose 解析替代，目标环境必须按 `docs/DEPLOYMENT.md` 和 `docs/FIRST_DELIVERY_REPORT.md` 重新验收。
