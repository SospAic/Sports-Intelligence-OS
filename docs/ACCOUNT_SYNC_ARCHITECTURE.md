# 账号同步高可用策略

本文记录账号同步的统一执行模型、并发边界、超时预算和降级语义。目标是让同步快速结束、可观察、可恢复，并且不把缺失数据伪装成成功数据。

## 执行阶段

1. 账号资料：校验适配器和凭证，读取公开资料及账号级指标。
2. 目录分页：只负责枚举作品 ID 和公开目录字段，提交页级 checkpoint。
3. 作品入库：按 external ID 幂等 upsert，保留标题、封面、发布时间、时长和来源。
4. 指标快照：把适配器返回的播放、点赞、评论、分享、收藏写入 append-only 快照；不可获得的私有指标保留条件提示。
5. 派生指标：只基于已确认的快照计算增长和互动指标。

目录失败、单条失败和指标失败是不同故障域：已经入库的作品不会因为后续详情或指标失败而回滚；首个目录页无法获取时才让任务进入可重试失败。

## 并发与预算

| 平台/阶段 | 方式 | 并发边界 | 说明 |
| --- | --- | ---: | --- |
| YouTube 目录 | yt-dlp flat | 1 个目录请求 | 目录是事实基线；详情是增强，失败时保留 flat 字段 |
| YouTube 详情 | yt-dlp | 默认 8，受全局并发限制 | 详情请求失败集中汇总，不逐条刷屏 |
| TikTok/Douyin 目录 | 授权浏览器公开页 | 2 个适配器调用上限；单账号页内顺序滚动 | 优先复用已授权 CDP 上下文，避免新上下文触发挑战页 |
| Bilibili 详情 | yt-dlp/公开页 | 默认 4 | 受平台和 workspace 上限共同限制 |
| 普通目录窗口 | 统一同步执行器 | 50 条/页，默认最多 5 页/次 | 初始回补和增量探测使用不同窗口 |
| 增量探测 | 已有账号 | 默认 15 条探测 | 遇到“新作品 → 已知作品”边界可提前结束 |

每个外部页请求都有独立 timeout；整个运行有硬时间预算；Celery 只对可重试故障做有限次数、指数退避重试。预算耗尽时保留 cursor 并标记 `degraded`，下次同步从 cursor 继续；cursor 闭合后才标记 `content_sync_complete=true`。

## 数据真实性规则

- 结构化响应中的 caption 才能进入 title；数字、`K/M/B` 和“播放”样式的文本只能进入 view_count。
- 没有标题时使用可识别的稳定 fallback（如 `视频 {external_id}`），不把播放量或占位文本冒充标题。
- 封面、发布时间和互动指标逐字段写入；字段缺失显示“需要配置条件”或 `—`，不估算、不用旧脏值覆盖新结果。
- 每条记录保留 `source_kind=live`、provider、external_id、fetched_at 和适配器方法信息。

## 故障与用户可见状态

- 公开页挑战/登录墙：返回明确的登录或人工完成验证条件，不把空目录当成功。
- 目录页超时：保留已入库前缀和 cursor，显示可继续同步的降级状态。
- 单作品详情失败：保留 flat/目录字段，并在页级日志中汇总失败数量。
- 私有分析字段缺少官方授权：只显示需要的具体条件。
- 可恢复的 yt-dlp fallback stderr 不直接渲染为 ERROR；真正的异常仍进入双层错误审计（代码详情 + 业务处理建议）。

## 已有数据更新规则（2026-08-14）

同步是“补充和校正”，不是“按本次响应重建”。作品通过平台 external ID
幂等匹配；详情、目录或降级响应缺少字段时，只更新本次明确返回的非空值。
媒体清单按文件名合并，字幕轨道和导出文件不会因为本轮没有重新下载而消失。
评论抓取是热门/分页增强，空结果或排名窗口变化不代表旧评论被平台删除，
因此只做非空字段更新和新增，不自动删除历史评论。这样作品再次同步后，
已有视频、原始信息、字幕、翻译轨道、字幕导出和评论都能保持可用。

这条规则由 `merge_media_manifest` 和评论更新分支共同执行，并由
`test_sync_data_retention.py` 覆盖空媒体观测、字幕追加、重复合并和空评论
刷新场景。需要清理脏数据时应使用独立的显式清理流程，不能把同步本身当作清理操作。
