## 四、发现的实质性矛盾与风险

**风险 1（高）— STATUS.md 与代码不符：Bilibili 公开 API 适配器缺失**
STATUS.md 2026-07-28 声称"完整实现 `BilibiliAdapter`（约 779 行）"。Grep 确认代码中**不存在 `bilibili.py` 或 `class BilibiliAdapter`**，仅有 `bilibili_browser.py`。现状是 Bilibili 只能走浏览器模式且该模式因登录墙失败。该声明已过时（公开 API 适配器疑似在 WBI 废弃时被一并移除），需纠正或将公开 API 适配器补齐。

**风险 2（中）— 评估文档高估组件工程化债务**
UI-UX 文档称 `ui.tsx` "~400 行、按钮/输入框通过导出 class 字符串实现而非组件"。实际文件 183 行，绝大多数已是真实 React 组件。结论：P1-1（Radix 重构弹窗）、P1-2（按钮/输入框组件化）的紧迫性低于文档判断，**但手写弹窗的焦点陷阱 / ESC / 点击外部关闭是否全部补齐仍需单独核验**（文档 P0-1 未提供代码证据）。

**风险 3（低）— accounts 页未使用统一 hook**
`accounts-client.tsx:49` 导入了 `useLocalStorageState`，但从未调用（死导入），页面直接用裸 `window.localStorage`。与 Feasibility "已实现 useLocalStorageState" 的机制描述不完全一致，且偏离统一约定，建议改用该 hook 或删除死导入。

**风险 4（低）— extraction_failure 约定范围被夸大**
Feasibility 写道"浏览器适配器提取失败时记录 warning + metadata 标记 extraction_failure"。实际仅 `youtube_browser.py` 落地，`bilibili_browser.py`/`tiktok_browser.py`/`douyin_browser.py` 仅用 `logger.debug`。陈述为复数与实际不符。
